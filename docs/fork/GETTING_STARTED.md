# Как начать работу с SA:COOP Friends

Мануал для тех, кто пишет код форка или помогает его проверять. Что и в каком порядке делаем — в
[ROADMAP.md](ROADMAP.md), список задач — в [BACKLOG.md](BACKLOG.md). Как устроен сам мод, подробно описал его автор
в [ARCHITECTURE.md](../ARCHITECTURE.md). Прочитайте хотя бы разделы «Сеть», «Игроки» и «Машины и NPC: кто чем
владеет».

## Первый вечер: короткий путь
1. Поставить Git, Python 3.12 и GitHub CLI ([что нужно](#что-нужно)).
2. Склонировать форк, подключить `upstream` — чтобы смотреть новые версии автора ([форк и клон](#форк-и-клон)).
3. Скачать компилятор и собрать: `tools/get-toolchain.ps1`, затем `python tools/build.py dist` ([сборка](#сборка)).
4. Поставить сборку в две копии игры и подключить одну к другой
   ([несколько копий игры на одном ПК](#несколько-копий-игры-на-одном-пк)).
5. Взять задачу из этапа 0 или 1 бэклога и сделать её по [порядку работы](#порядок-работы).

## Что нужно
| Что | Зачем | Где взять |
|---|---|---|
| Windows 10 или 11, x64 | Сборка, игра и сервер — под Windows | — |
| Git | Код | git-scm.com |
| Python 3.12 | `tools/build.py` и проверки (только стандартная библиотека) | python.org, при установке отметить «Add to PATH» |
| PowerShell 5.1+ | `tools/get-toolchain.ps1` | есть в Windows |
| GitHub CLI `gh` | Issues, PR, чужие PR сообщества | cli.github.com |
| GTA San Andreas 1.0 US | Проверка в игре. Нужен `gta_sa.exe` размером 14 383 616 байт | Steam и Rockstar Launcher — откатить программой GTA SA Downgrader |
| 5–20 ГБ на диске | Копии игры для стенда: одна копия около 4,7 ГБ, с жёсткими ссылками почти ничего | — |
| Редактор | VS Code с расширением clangd: `build.py` пишет `compile_commands.json` в корень, подсказки работают сразу | code.visualstudio.com |

Компилятор (llvm-mingw, clang под 32-битную Windows) ставится скриптом в папку проекта, отдельно ничего ставить не
нужно.

## Инфраструктура
**Решение: GitHub, публичный форк.** Почему не GitLab и не Azure:

| | GitHub | GitLab | Azure DevOps |
|---|---|---|---|
| Где апстрим и PR сообщества | здесь: PR автору и чужие PR (№32, №33, №49) в два клика | нет, нужно зеркало | нет, нужно зеркало |
| CI под Windows для публичного репозитория | бесплатно, без лимита минут на стандартных раннерах | 400 минут в месяц на всё в бесплатном тарифе | бесплатный хостинг сборок только по заявке, одобрение может затянуться |
| CI для приватного репозитория | 2000 минут в месяц, Windows-минуты дороже Linux | те же 400 минут | 1 параллельная сборка, 1800 минут в месяц, тоже по заявке |
| Раздача сборок друзьям | Releases, бесплатно | Releases, бесплатно | Artifacts, неудобно для игроков |
| Задачи | Issues и Projects, бесплатно | Issues и доски, бесплатно | Boards, бесплатно до 5 человек |

Форк публичного репозитория на GitHub всегда публичный. Если нужен приватный, придётся создать отдельный репозиторий
и залить туда код. Тогда сборки тратят 2000 бесплатных минут в месяц, а PR в апстрим делать неудобнее. Лицензия MIT
разрешает публичный форк, нужно только сохранить файл `LICENSE` с копирайтом автора.

**Сервер для игры (этап 2) — бесплатные варианты:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| ПК друга с «белым» IP | бесплатно, без лимитов | нужен постоянный IP и открытый UDP-порт; когда друг выключил ПК, сервера нет |
| Oracle Cloud Always Free | 2 маленькие AMD-машины (1/8 ядра, 1 ГБ) или до 4 ядер ARM с 24 ГБ; около 10 ТБ исходящего трафика в месяц | нужна банковская карта для проверки, не со всех стран регистрация проходит. Простаивающую машину (меньше 20% нагрузки за 7 дней) Oracle может забрать. Под Linux нужен SES-02, ARM — тоже |
| playit.gg (бесплатный туннель) | работает без белого IP, уже описан в инструкции автора («Способ Б») | лишний переход через их узел, задержка выше |
| Radmin VPN или ZeroTier | ноль кода: все в одной виртуальной сети, подключение по её IP | каждый ставит программу; у ZeroTier бесплатный тариф ограничен числом устройств |

Если бесплатное не подойдёт, самый дешёвый VPS стоит несколько долларов в месяц и решает всё сразу. Лимиты
бесплатных тарифов проверены 24 октября 2026 года и меняются: перед выбором сверьтесь со страницами сервисов.

## Форк и клон
1. На странице [Karimov-Akbar/sa-coop](https://github.com/Karimov-Akbar/sa-coop) нажать Fork и в поле Repository name указать `sa-coop-friends`.
2. В форке на вкладке Actions включить workflows.
3. В Settings → Branches защитить `main`: только через PR и с зелёной сборкой.

```bash
git clone https://github.com/<ваш-логин>/sa-coop-friends.git
```

```bash
git remote add upstream https://github.com/Karimov-Akbar/sa-coop.git
```

Ветки: `main` — то, что раздаём друзьям. Работа идёт в ветках по задачам: `net-01-password-order`,
`mp-03-successor`.

## Сборка
Из корня репозитория. Скачать компилятор (один раз, архив на пару сотен мегабайт):

```bash
powershell -ExecutionPolicy Bypass -File tools/get-toolchain.ps1
```

Собрать всё и разложить пакет для игры:

```bash
python tools/build.py dist
```

| Команда | Что делает |
|---|---|
| `python tools/build.py` | Собирает всё (release) в `build/release/bin` |
| `python tools/build.py dist` | Ещё и раскладывает `dist/SA-COOP/` и `dist/SA-COOP.zip` — то же, что в релизе |
| `python tools/build.py --debug dist` | Без оптимизаций (`-O0`) в `build/debug`, удобно для отладки |
| `python tools/build.py client` | Только `coop.dll`. Есть ещё цели `server` и `loader` |
| `python tools/build.py --clean` | Удаляет `build/release` и `build/debug` |
| `python tools/fsd_check.py` | Проверка слоёв (см. «Правила кода») |
| `python tools/i18n_check.py` | У каждого русского текста игры есть английский. Перед запуском в PowerShell: `$env:PYTHONIOENCODING = "utf-8"` |

Что получается:
- `coop.dll` — клиент, в пакете он называется `coop.asi`;
- `coop-server.exe` — сервер;
- `vorbisFile.dll` — загрузчик ASI для чистой игры;
- `coop.pdb` — символы для разбора `crash.log`.

## Установка в копию игры
Для разработки держите отдельные копии игры, а не ту, в которую играете.
1. Скопировать содержимое `dist/SA-COOP/` в папку игры, рядом с `gta_sa.exe`.
2. Один раз запустить `install.bat`. В чистой игре он поставит загрузчик ASI, в сборке с загрузчиком ничего не
   изменит.
3. После новой сборки достаточно заменить `coop.asi` и папку `coop` (настройки в `coop\coop.ini` не перезаписываются).

## Несколько копий игры на одном ПК
Так проверяется всё, кроме подключения через интернет. Пока нет скрипта стенда (INF-04), делаем руками.

**1. Копии игры с жёсткими ссылками.** Крупные файлы общие и почти не занимают места. Работает только на одном
диске. Если какой-то мод правит `gta3.img` на месте, правка попадёт во все копии.
```powershell
$base = "D:\gta-dev\base"   # чистая GTA SA 1.0 US
foreach ($n in 1..4) {
  $dst = "D:\gta-dev\P$n"
  Get-ChildItem $base -Recurse -File | ForEach-Object {
    $target = Join-Path $dst $_.FullName.Substring($base.Length + 1)
    New-Item -ItemType Directory -Force (Split-Path $target) | Out-Null
    if ($_.Length -gt 10MB) { New-Item -ItemType HardLink -Path $target -Target $_.FullName | Out-Null }
    else { Copy-Item $_.FullName $target }
  }
}
```

**2. Мод в каждую копию:** содержимое `dist/SA-COOP/` и один раз `install.bat`.

**3. Свой `coop\coop.ini` у каждой копии.** Файл создаётся при первом запуске; можно запустить один раз и
поправить. Пример для хоста P1:
```ini
[player]
name = P1

[connect]
auto_connect = 1
mode = host
port = 7788
; номер сохранения в папке user_dir, которое хост загрузит сам
load_slot = 1

[game]
windowed = 1
width = 960
height = 540
window_x = 0
window_y = 0
window_title = P1
multi_instance = 1
; своя папка сохранений и настроек, иначе копии мешают друг другу
user_dir = D:\gta-dev\P1\user

[debug]
overlay = 1
verbose_log = 1
; локальным подключениям брандмауэр не нужен
firewall_prompt = 0
```
У P2–P4:
- в `[player]` — `name = P2`, `P3`, `P4`;
- в `[connect]` — `mode = join` и `host = 127.0.0.1` (без `load_slot`);
- в `[game]` — свои `window_x`, `window_y`, `window_title` и `user_dir`.

Положите сохранение (`GTASAsf1.b`) в `user_dir` хоста.

**4. Запуск:** сначала P1, потом остальные. Каждую копию запускать из её папки:
```powershell
foreach ($n in 1..2) { Start-Process "D:\gta-dev\P$n\gta_sa.exe" -WorkingDirectory "D:\gta-dev\P$n"; Start-Sleep 5 }
```

Четыре копии в окне тянет средний ПК. Если тормозит, уменьшите `width`/`height` и дальность прорисовки в настройках
игры каждой копии.

## Где что лежит
Все пути — внутри папки копии игры.

| Файл | Что в нём |
|---|---|
| `coop\coop.ini` | Настройки клиента |
| `coop\coop.log`, `coop\coop.old.log` | Журнал клиента, текущий и прошлый запуск |
| `coop\crash.log` | Отчёт о вылете: исключение, регистры, стек. Разбирается с `coop.pdb` той же сборки |
| `coop\server-data\server.log` | Журнал сервера, если эта копия была хостом |
| `coop\server-data\profiles\` | Профили напарников (прогресс) |
| `coop\server-data\world\` | Последний снимок мира |
| `coop\server-data\invite.txt` | Последний код приглашения |
| `coop\server.ini` | Настройки сервера, если запускать его отдельно |

`verbose_log = 1` пишет подробный журнал и включает детектор зависаний. `overlay = 1` показывает на экране состояние
сети (после INF-06 — ещё и трафик по типам сообщений и время модулей).

## Как проверять изменения
| Что меняли | Чем проверять |
|---|---|
| Сервер, протокол, подключение, переподключение | Бот: `tools/fork/bot-tests.ps1` (подробнее ниже), затем 2 копии |
| Синхронизация игроков, машин, NPC, миссий | 2 копии на одном ПК |
| Всё для 3–4 игроков | 3–4 копии, сценарии из «Готово, когда» задачи |
| NAT, ретранслятор, VPS | Реальные сети: друг или мобильный интернет через точку доступа |
| Оптимизация | Счётчики INF-06 до и после, одна и та же сцена |

**Бот для сервера (`coop-bot.exe`).** Собрать: `python tools/build.py server bot` (или просто `python tools/build.py`).
Запустить все сценарии: `powershell -ExecutionPolicy Bypass -File tools/fork/bot-tests.ps1`. Бот сам запускает свежий
`coop-server.exe` на каждый сценарий (порты с 7790, данные — во временной папке `coop-bot`), игра не нужна.
- `--list` — список сценариев, `--only chat,password` — только эти;
- `--connect 1.2.3.4:7788` — против уже запущенного сервера (только сценарии, которым не нужен свой сервер);
- код выхода: 0 — всё прошло, 1 — ошибка, 2 — неверная команда. «известный баг» — ожидаемый провал задачи из бэклога.

Чинишь сетевой баг — сначала сценарий в `src/bot/features/scenarios/Scenarios.cpp`, который его ловит, потом
исправление. Под Linux бот и сервер запускаются в Wine: `wine build/release/bin/coop-bot.exe`.

Перед PR, кроме сценария задачи, пройдите короткий дым-тест на двух копиях:
- хост загрузил сохранение, напарник получил мир;
- оба прошли и проехали квартал, напарник сел пассажиром (G);
- миссия у Свита стартует, когда оба в маркере;
- напарник вышел и зашёл снова.

## Порядок работы
1. Взять задачу из бэклога (после INF-08 — issue на доске), назначить на себя.
2. Ветка от свежего `main`: `git switch -c net-01-password-order`.
3. Коммиты на русском, как у автора, с номером задачи: `NET-01: пароль проверяется до замены соединения`.
4. PR в `main` своего форка. В описании — что сделано, почему и как проверено: какой сценарий, сколько копий,
   какие логи.
5. CI должен быть зелёным. Если задача меняет поведение в игре — ревью вторым человеком и проверка на стенде.
6. После слияния — отметить задачу в бэклоге или закрыть issue.

## Правила кода
Пишем так же, как автор, чтобы правки было легко отдать ему и подтянуть его обновления.
- **Слои FSD:** `app → pages → widgets → features → entities → shared` у каждой программы, общий код — в
  `src/common`. Слой подключает только нижние слои и свой слайс. Проверяет `tools/fsd_check.py`, он же в CI.
- **Тексты игры** — только через `TR("русский", "english")`. `tools/i18n_check.py` падает, если нет английского.
- **Комментарии** — на английском и объясняют «почему»: какой баг, какой адрес движка, какой issue.
- **Адреса движка** подписывайте именем функции из gta-reversed или plugin-sdk, как в коде автора:
  `Call<0x5696C0, float>(...)  // CWorld::FindGroundZFor3DCoord`.
- **Данные из сети** читать только через `Reader` и проверять до вызова движка: модели, индексы, указатели.
- **Изменилось поведение** — опишите его в `docs/fork/`. `docs/ARCHITECTURE.md` — документ автора, его не правим.
- **Изменился протокол** — поднимите номер протокола форка: `kForkProtocolRevision` в `Version.h` +1 (INF-03).
- Новые зависимости — только с лицензией, совместимой с MIT, в `third_party/`, с её файлом лицензии.

## Новые версии автора
Форк идёт своим путём: версии автора **не сливаем** (`git merge upstream/main` не делаем), но следим за ними и
вручную переносим удачные исправления. Автору свои правки не отправляем.

Когда автор выпустил версию (новости — в его [Telegram](https://t.me/cavalier_mods) и Releases):

```bash
git fetch upstream
```

```bash
git log --oneline main..upstream/main
```

Для каждого интересного коммита — посмотреть, что он меняет:

```bash
git show <коммит>
```

Подходит — перенести в ветку задачи, указав источник:

```bash
git cherry-pick -x <коммит>
```

`-x` допишет в сообщение «cherry picked from commit …»: авторство и источник остаются в истории. Если коммит не
ложится на наш код, перенести исправление руками и написать в сообщении, из какого коммита автора оно взято. Дальше
как обычно: сборка, бот, стенд, PR. Перенесённое записать в `docs/fork/CHANGELOG.md`.

Если перенесённая правка меняет протокол, поднимите номер протокола форка: `kForkProtocolRevision` в
`src/common/config/version/Version.h` +1. `kUpstreamProtocol` хранит номер автора, на котором форк отделился, и не меняется.

PR сообщества в репозиторий автора, например №32, — так же: в отдельную ветку, ревью, стенд, потом слияние, авторство
сохраняется:

```bash
git fetch upstream pull/32/head:pr-32
```

```bash
gh pr diff 32 -R Karimov-Akbar/sa-coop
```

## Релиз для друзей
1. Поднять версию в `src/common/config/version/Version.h`: `COOP_VERSION_STR "0.3.0.N"`. Только цифры и точки,
   иначе `build.py` не соберёт ресурс версии.
2. Описать изменения в `.github/fork-release-notes.md`: workflow берёт его текстом релиза. `.github/release-notes.md`
   — файл автора, его не трогаем.
3. Слить в `main`, поставить тег и отправить его:

```bash
git tag v0.3.0.1
```

```bash
git push origin v0.3.0.1
```

GitHub Actions соберёт `SA-COOP.zip` и опубликует релиз. Друзьям — ссылка на Releases форка. Версии форка и
апстрима друг к другу не подключаются (после INF-03), поэтому обновляться должны все.

## Выделенный сервер
Полная инструкция появится в SES-01. Уже сейчас работает так:
1. На машине с «белым» IP положить `coop-server.exe` (из `dist/SA-COOP/coop/`). Рядом при первом запуске
   создаётся `server.ini`.
2. В `server.ini`, раздел `[server]`:
   - `port`, `password`;
   - `max_players` — пока не больше 2, до MP-02;
   - `host = <ник хоста>` — роль хоста не уйдёт к тому, кто зашёл раньше;
   - `internet = 0` — UPnP и коды приглашения на сервере с белым IP не нужны.
3. Открыть UDP-порт: в брандмауэре Windows и в панели облака (у Oracle — Security List).
4. Все, и хост тоже, подключаются вкладкой «Подключиться» по `IP:порт`. Хост загружает сохранение, и мир уходит
   напарникам.

Под Linux сервер пока не собирается (SES-02). Можно попробовать Wine, но это не проверено.

## Частые проблемы
| Симптом | Что делать |
|---|---|
| `toolchain not found` | Запустить `tools/get-toolchain.ps1` |
| Антивирус удаляет `coop-server.exe` или `coop.asi` | Добавить в исключения папку репозитория и копии игры |
| Окно F9 не появляется | Не запущен `install.bat` или в сборке нет загрузчика ASI |
| Копии игры делят сохранения и настройки | У каждой свой `user_dir` |
| Второй игрок: «ник уже на сервере» | У копий одинаковый `name` в `coop.ini` |
| «Другая версия мода» | Клиент и сервер разных сборок. Форк и апстрим не смешиваются (INF-03) |
| Друг не подключается через интернет | `server.log` хоста. Если ретранслятор не работает, проверить ключ metered.ca (NET-04) или перейти на выделенный сервер |
