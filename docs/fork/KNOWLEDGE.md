# База знаний SA:COOP Friends

Сводка всего, что выяснено при разборе проекта 24–25 октября 2026. Файл для людей и для Claude в новой сессии:
читать перед работой, дополнять по ходу. План — [ROADMAP.md](ROADMAP.md), задачи — [BACKLOG.md](BACKLOG.md),
мануал — [GETTING_STARTED.md](GETTING_STARTED.md).

## 1. Контекст
- **Апстрим:** [Karimov-Akbar/sa-coop](https://github.com/Karimov-Akbar/sa-coop), MIT. Кооператив GTA San Andreas 1.0 US
  на двоих: сюжет идёт у хоста, напарник играет своим CJ в мире хоста.
- **База разбора:** коммит `636b515` (версия 0.3.0, протокол 19). На 25.10 апстрим ушёл на `d4dfb3a`, но изменился
  только README (ссылка на Telegram). Код тот же.
- **Цель форка:** игра с друзьями до 4 человек, стабильное подключение, меньше выкидываний в меню. Не масс-проект:
  защиту от злоумышленников и «энтерпрайзные» механизмы не делаем, пока нет реальной проблемы.
- **Владелец форка** говорит по-русски, хочет бесплатную инфраструктуру. Решено: GitHub, публичный форк.
- **Ограничение:** Claude не может запускать игру. Сетевую часть проверяем ботом (INF-05), игровую — пользователь на
  стенде из нескольких копий (`multi_instance`).

## 2. Как устроен мод (ключевое)
Подробно — в [ARCHITECTURE.md](../ARCHITECTURE.md) автора. Самое нужное:

**Программы:**
- `coop.dll`, он же `coop.asi` — клиент внутри `gta_sa.exe`.
- `coop-server.exe` — ретранслятор. Хост запускает его из игры, но сервер умеет работать и отдельно.
- `vorbisFile.dll` — загрузчик ASI для чистой игры.

**Сборка:** llvm-mingw (clang, i686), `python tools/build.py dist`. Версия в `Version.h` — только цифры и точки.

**Слои FSD:** `app → pages → widgets → features → entities → shared`, проверяет `tools/fsd_check.py`. Все тексты —
через `TR("ru", "en")`, проверяет `tools/i18n_check.py`.

**Сеть:**
- ENet поверх UDP, 4 канала: надёжный, состояния, голос, файлы. MTU 1200, через ретранслятор 576.
- Звезда через сервер. Сообщения с id ≥ 64 сервер пересылает **всем** остальным, подставляя отправителя, и не
  разбирает.
- Клиентский ENet работает в своём потоке, игра забирает сообщения раз в кадр.
- Интернет: UPnP → STUN → код приглашения (IP:порт + случайный ключ) → пробивка NAT через публичный ntfy.sh →
  TURN только с аккаунтом metered.ca.

**Игроки:**
- Копия удалённого игрока — настоящий `CPlayerPed`, создаётся `CREATE_PLAYER` в слоте `CWorld::Players[1]`.
- Управляется подменой контекста (пад, камера, статистика), как в SA-MP и MTA.
- Все копии делят `CPlayerPedData` слота: для 3+ игроков это лечит PR №32.

**Владение:**
- У каждой машины, NPC и объекта один владелец, у остальных — «зеркало».
- Id сущности: `(id игрока + 1) << 12 | n`, хватает на 15 игроков.
- Население рядом с хостом генерирует только хост. Чужие сущности передаются игроку, который к ним ближе.

**Миссии:**
- Идут только у хоста. Тексты, метки, маркеры, катсцены, звук, затемнения пересылаются напарнику отдельными
  сообщениями.
- Миссия стартует, когда в маркере все.
- После каждой пройденной миссии напарник **перезагружает весь мир** хоста.

**Тесты:** у автора их нет в репозитории (его бот и стенд приватные). В форке есть свой бот `coop-bot.exe` для
сервера и протокола (INF-05, раздел 9).

## 3. Цифры трафика (по коду)
| Поток | Частота | Размер |
|---|---|---|
| Игрок пешком | 30 Гц и сразу при смене кнопок | ~77 байт → ~2,3 КБ/с |
| NPC | 10 / 5 / 2,5 Гц до 40 / 80 / дальше м | ~40–50 байт |
| Машины NPC в движении | 10 Гц на любом расстоянии, стоящие раз в 2 с | ~46 байт |
| Голос | 50 кадров/с, IMA ADPCM 16 кГц | ~8,5 КБ/с на говорящего |

Людная улица — около 20 КБ/с от владельца населения. Вчетвером сервер пересылает каждое сообщение трём получателям:
голос троих говорящих — около 75 КБ/с исходящего у хоста.

## 4. Проверенные находки
Всё подтверждено чтением кода. Подробности, ссылки и критерии готовности — в бэклоге под указанным id.

**Сессия и подключение:**
- Нет автоматического переподключения. После обрыва — меню, при входе мир грузится заново (SES-03).
- Сервер, запущенный из игры, убивается вместе с ней через job object: вылет хоста выкидывает всех (SES-05).
- Сбой TURN (HTTP 401) виден только в `server.log`, а код приглашения задерживается на 15 с (NET-04, #64).
- Ключ кода приглашения случайный при каждом запуске (NET-07).
- Продление разрешений TURN после неудачи повторяется только через 240 с при сроке 300 с (NET-05). Ожидание ответа
  TURN до 6 с блокирует пересылку игры (NET-06).
- Ретранслятор ищется, только если сработали STUN и ntfy, и один раз (NET-08).
- Отмена подключения по коду блокирует игровой поток через `join` (NET-09).
- Пароль проверяется после замены старого соединения с тем же ником (NET-01). Приветствие с протоколом 0 проходит
  (NET-02).
- Слот нужен ещё до приветствия: вчетвером вернувшийся после вылета получит «нет мест» (NET-03).
- Проверка main.scm сравнивает только размеры (SES-07).
- Прогресс напарника хранится только на ПК хоста (SES-08).

**Стабильность:**
- Копии машин не проверяются заново после шага игры (STB-01).
- Переполненная очередь хранит старые состояния и выбрасывает новые (STB-02).
- Пулы и память стриминга движка не подняты (STB-05).
- Запись мира и профилей: синхронно в сетевом потоке, ожидание сдаётся через 5 с (STB-03, STB-04).

**Четыре игрока:**
- Лимит — одна константа `kGamePlayers = 2`.
- Каждый оставшийся забирает вещи ушедшего: дубли (MP-03).
- Население и поезда подавляются только рядом с хостом (MP-04).
- Получатели создают копии любых сущностей независимо от расстояния (MP-05).
- Id огня без отправителя (MP-06).
- Гараж отдаёт машины всем напарникам (MP-07).
- Копы идут к последнему разыскиваемому из цикла (MP-08).
- Места в машине выбираются без резерва (MP-09).
- Катсцены, переносы и возрождение ставят всех в одну точку (MP-10, MP-16).
- В подработку берётся один помощник (MP-12).

**Игра:**
- Награда напарника — разница кошелька хоста (GAME-01).
- Чат на T мешает читам (UX-01, подтверждено в #69).
- Голос обрабатывается из игрового кадра и пропадает на загрузках (OPT-02).
- Лут убитых виден только убийце (UX-04).

**Заготовки автора:**
- В протоколе объявлены, но не используются: `G_PLAYER_AIM`, `G_PLAYER_SPAWN`, `G_PLAYER_WEAPONS`, `G_BULLET`,
  `G_PED_STATUS`, `G_WANTED`, `G_SCRIPT_VARS`, `G_GAME_EVENT`.
- `kMaxPlayers = 4` в протоколе, `--max` у сервера есть.

## 5. Разбор Астры (другой ИИ): итог проверки
- Около 30 её утверждений проверены по коду, фактических ошибок нет. Её находки для 4 игроков вошли в бэклог: MP-03,
  MP-07, MP-08, MP-09, MP-12, NET-01, NET-03, NET-05, NET-06, NET-08, NET-09, STB-01, STB-02, GAME-01.
- **Перегибает:** идентификаторы операций, двухфазные подтверждения и «поколения» везде; контракты сообщений;
  буфер снимков. Это LTR-03 … LTR-05 — только если тесты покажут нужду.
- **Пропустила:** лимиты движка, 15 с ожидания и случайный ключ кода, частоту машин, неиспользуемые сообщения,
  выделенный сервер как первый шаг, неслитые PR сообщества.
- **Исправленные мои ошибки:** подработка не «для всех», а на одного помощника; копии игроков — не 1–2 недели,
  PR №32 решает это в 42 строки.

## 8. Решения
- Инфраструктура: GitHub, публичный форк, Actions, Releases, Issues и Projects. GitLab — 400 минут CI в месяц;
  Azure DevOps — бесплатные сборки по заявке.
- Сервер для игры: выделенный — ПК друга с белым IP, Oracle Always Free после SES-02, playit.gg или Radmin VPN как
  запасные.
- Транспорт остаётся ENet. Сюжет остаётся у хоста. Цель — 4 игрока, не 8.
- Версия форка `0.3.0.N`, протокол `1000 + протокол апстрима`.
- **Свой путь (решение владельца 25.10):** версии автора не сливаем, правки автору не отправляем. Новые версии
  автора просматриваем и переносим удачные исправления вручную (`cherry-pick -x`, INF-09). Код меняем точечно:
  синхронизацию автора чиним и расширяем, а не переписываем.

## 9. Состояние работы
- Проект называется **SA:COOP Friends**, репозиторий — настоящий форк
  [Pomudop/sa-coop-friends](https://github.com/Pomudop/sa-coop-friends) («forked from Karimov-Akbar/sa-coop»): вся
  история апстрима до `d4dfb3a`, сверху коммиты форка — база знаний, атрибуция и правовая часть (раздел 10).
  CI (`build`, `fork-guard`) зелёный.
- Сделаны INF-03 (протокол 1019, версия 0.3.0.1) и INF-10 (форк отличим в F9, логах, ресурсах файлов, инструкции
  и релизе). Проверено сборкой и проверками проекта; в игре и ботом не проверялось — бота ещё нет (INF-05).
- Сделан INF-05: бот `coop-bot.exe`, 13 сценариев против настоящего сервера. Шаг в CI (часть INF-07).
- Следующие шаги: INF-02 у владельца (сборка на Windows и сравнение архива с CI), NET-01 и NET-02 (бот уже
  ловит оба), остальные P0 этапа 1, INF-08 (бэклог в Issues), BUG-05.

**Бот подтвердил на живом сервере (25.10):** NET-01 — подключение с ником игрока, молчащего 3 с, и неверным паролем
выкидывает этого игрока; NET-02 — приветствие с протоколом 0 принимается. Ретрансляция на локальной машине: 90 из 90
состояний, задержка ~2 мс, игроку в меню состояния не идут, надёжные события приходят все и по порядку.

**Windows-программы проекта запускаются под Wine (25.10).** Wine 9.0 с `wine32` (Ubuntu): `coop-server.exe` и
`coop-bot.exe` работают, пути — `Z:/...`. Так сеть и сервер можно проверять на Linux, в том числе в облачной сессии
Claude; игру — нет.

**Сборка под Linux работает (25.10).** Тот же llvm-mingw `20261006`, но сборка `ucrt-ubuntu-22.04-x86_64`, собирает
все три программы и `dist` без правок кода. `build.py` ищет `toolchain/llvm-mingw/bin/i686-w64-mingw32-*.exe`: под
Linux туда кладутся обёртки-скрипты (`exec <путь>/i686-w64-mingw32-clang++ "$@"`). Символьные ссылки не подходят:
по имени с `.exe` clang не понимает, что он `clang++`, и не линкует libc++. Пригодится для бота в CI (INF-07) и
сервера под Linux (SES-02).

**Сверка с кодом `d4dfb3a` (25.10).** Проверены по коду: `kGamePlayers = 2` и `kMaxPlayers = 4` (Protocol.h),
пропуск протокола 0 (NET-02), замена старого соединения до проверки пароля (NET-01), чат на T (`chat = 84`, UX-01),
ожидание ретранслятора 150 × 100 мс и случайный ключ кода (NET-04, NET-07), порог очереди 4000 (STB-02), машины
NPC раз в 100 мс на любом расстоянии (OPT-03), `KILL_ON_JOB_CLOSE` (SES-05), голос 16 кГц кадрами по 20 мс, восемь
объявленных, но неиспользуемых сообщений. Всё совпадает.

## 10. Право и атрибуция
Подробно — [LEGAL.md](../../LEGAL.md) и [NOTICE.md](../../NOTICE.md) в корне.
- **Автор:** лицензия MIT требует только сохранить копирайт и текст лицензии. `LICENSE` не трогаем, история
  коммитов автора сохранена. Главная страница форка — `.github/README.md`: GitHub показывает её вместо
  `README.md` автора, поэтому README автора остаётся без изменений.
  Форк везде называем форком и ссылаемся на оригинал; логотип автора как свой бренд не используем.
- **Rockstar / Take-Two:** снимают с GitHub прежде всего декомпилированный код игры (re3, reVC) и всё, что
  содержит файлы игры или помогает пиратству. Моды-инжекторы на адресах (SA-MP, MTA) живут годами. У нас: файлов
  игры нет ни в дереве, ни в истории (проверено по всем коммитам), стороннего кода Rockstar нет, проект
  некоммерческий.
- **Что охраняет:** `tools/fork/guard_check.py` и workflow `fork-guard.yml` валят CI, если в git попал файл игры,
  бинарник, файл больше 5 МБ или пропал копирайт автора. `.gitignore` дополнен файлами игры.
- **Зона внимания:** `tools/re/` автора упоминает HOODLUM-версию exe и читает `gta_sa.pdb`; в
  `Version.h` и `Game.h` тоже упомянут HOODLUM. Самих файлов нет, скрипты только анализируют копию разработчика.
  Оставлено как у автора; если понадобится — удалить `tools/re/` из дерева форка.
- **Донаты:** в форке не собираем. Ссылка на поддержку автора остаётся в README автора.
